## 3. Auditoría Estática de Arquitectura y Código Fuente

### 3.1 ViewModel de Chat y Clean Architecture MVVM (`REQ-022`, `P22`)
- **Archivos auditados**:
  - `apps/web/hooks/useCoachConversation.ts`
  - `apps/web/components/CoachChat.tsx`
  - `apps/web/components/CoachChatScreen.tsx`
- **Hallazgos**:
  1. `CoachConversationViewModel` encapsula completamente la lógica de orquestación, estados de guardado (`idle`, `saving`, `saved`, `error`, `conflict`), paginación (`loadNextPage`) y resolución de concurrencia.
  2. Los componentes de React `CoachChat` y `CoachChatScreen` se encuentran completamente desacoplados: no realizan llamadas `fetch` directas ni importan el SDK `@supabase/supabase-js`.
  3. Toda la comunicación con backend se canaliza a través de métodos del ViewModel o del adaptador `ClientAuthService`.
  4. La suite de pruebas `architecture-viewmodel.test.mjs` y `architecture.test.mjs` valida estáticamente que el dominio (`apps/web/lib/chat/domain`) no tiene dependencias de React, Next.js ni Supabase.

### 3.2 Autenticación Supabase OTP y Cierre de Sesión Seguro (`REQ-004`, `REQ-013`)
- **Archivos auditados**:
  - `apps/web/app/login/page.tsx`
  - `apps/web/lib/infra/auth/clientAuthService.ts`
- **Hallazgos**:
  1. `apps/web/app/login/page.tsx` implementa un flujo en dos fases: solicitud de OTP y verificación de código de 6 dígitos.
  2. `clientAuthService.ts` configura `shouldCreateUser: false` en `signInWithOtp`, garantizando que únicamente usuarios explícitamente invitados por administración puedan acceder (ADR-004).
  3. Ante cierre de sesión (`handleLogout`), `CoachChatScreen.tsx` invoca `clearState()`, vaciando de inmediato los mensajes, borradores y datos de conversación en memoria del cliente antes de invocar `authService.signOut()`, evitando fugas de información privada entre sesiones en el mismo terminal (REQ-013).

### 3.3 Importación Opt-in e Integridad Byte a Byte de `localStorage` (`REQ-011`, `REQ-012`)
- **Archivo auditado**: `apps/web/lib/coachStorage.ts`
- **Hallazgos**:
  1. `getSurvivingLegacyChats` recupera todas las conversaciones locales sin truncarlas al límite de 4.
  2. `computeChatDigest` implementa un algoritmo SHA-256 determinista (`sha256Sync`) sin dependencias externas, asegurando hashing idéntico de mensajes canónicos.
  3. `executeOptInImport` exige confirmación explícita de cuenta destino (`confirmed === true`). Detecta duplicados mediante digest para evitar reenvíos innecesarios.
  4. La función compara el contenido crudo antes y después de la importación (`initialRaw === finalRaw`) y nunca borra ni altera el `localStorage` original. Las pruebas unitarias confirman la preservación byte a byte incondicional.

### 3.4 Retiro Definitivo del Selector de Modelos (`REQ-017`)
- **Archivo auditado**: `apps/web/components/CoachModelSelect.tsx`
- **Hallazgos**:
  1. Se eliminaron por completo las etiquetas interactivas `<select>` y `<option>`.
  2. El componente renderiza exclusivamente un badge informativo estático: `<span className="coach-model-badge">GPT-6 Luna · High</span>` acompañado de un icono decorativo (`✦`).
  3. No existen controles accesibles ni mecanismos ocultos para alternar modelos desde el cliente web.

### 3.5 Preservación de Geometría Centrada Responsive (`REQ-001`, `REQ-002`, `REQ-003`)
- **Archivo auditado**: `apps/web/app/globals.css`
- **Hallazgos**:
  1. Línea 121: `.app-main > main` define `width: 100%; max-width: 1120px; margin: 0 auto; padding: 1.5rem 28px 3rem;`.
  2. Línea 647: Para `@media (max-width: 800px)`, el padding lateral pasa a `16px`, manteniendo centrado sin overflow horizontal.
  3. Línea 508: `.chat-composer` define `max-width: 880px; margin: 0 auto;`.
  4. El scroll interno horizontal de gráficos y tablas se preserva mediante contenedores dedicados (`.prep-chart-wrap`, `.projection-table-wrap`).
