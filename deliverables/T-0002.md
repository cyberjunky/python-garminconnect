# Entrega T-0002: Migración Supabase garmin_tokens y Adaptadores Python

## 1. Resumen de Implementación

Se completó la implementación técnica para la persistencia y sincronización segura de los tokens de autenticación de Garmin en Supabase, satisfaciendo los requisitos **REQ-001** y **REQ-005** especificados en `specs/001-recurring-token-sync/spec.md`.

## 2. Componentes Implementados

1. **Migración SQL y Esquema Canónico**:
   - Archivo creado: [`supabase/migrations/20261011_garmin_tokens.sql`](file:///Users/alarcondiegof/ies-projects/python-garminconnect/supabase/migrations/20261011_garmin_tokens.sql)
   - Archivo actualizado: [`supabase/schema.sql`](file:///Users/alarcondiegof/ies-projects/python-garminconnect/supabase/schema.sql)
   - Estructura:
     * Tabla `public.garmin_tokens` con clave primaria `id uuid`, clave foránea `user_id uuid references public.users(id) on delete cascade`, `token_data jsonb not null`, marcas de tiempo `created_at` y `updated_at`, y restricción de unicidad `unique (user_id)`.
     * Row Level Security (RLS) habilitado.
     * Política `service_role_all` exclusiva para el rol `service_role`.
     * Permisos explícitamente revocados para roles `anon` y `authenticated`, garantizando aislamiento de credenciales sensibles.

2. **Adaptadores en Cliente Supabase**:
   - Archivo modificado: [`services/collector/supabase_client.py`](file:///Users/alarcondiegof/ies-projects/python-garminconnect/services/collector/supabase_client.py)
   - `get_garmin_tokens_from_supabase(user_id: str = DEFAULT_USER_ID) -> dict[str, Any] | None`:
     Consulta `public.garmin_tokens` y retorna el diccionario `token_data` si existe o `None`.
   - `upsert_garmin_tokens_to_supabase(token_data: dict[str, Any], user_id: str = DEFAULT_USER_ID) -> dict[str, Any] | None`:
     * Implementa validación no destructiva estricta según **REQ-005**: valida que `token_data` sea un diccionario no vacío que contenga al menos una clave de token no vacía (`di_token` o `di_refresh_token`). Si la carga es nula, vacía o inválida, no interactúa con la base de datos y retorna `None` sin sobreescribir tokens previos.
     * En caso válido, realiza `upsert` con conflicto en `user_id` y actualiza `updated_at`.

3. **Integración en Flujo de Autenticación Garmin**:
   - Archivo modificado: [`scripts/garmin_auth.py`](file:///Users/alarcondiegof/ies-projects/python-garminconnect/scripts/garmin_auth.py)
   - `restore_tokens_from_supabase(dest_store: str | None = None) -> bool`:
     Restaura tokens desde Supabase y los persiste localmente de manera atómica con permisos seguros `0o600` / `0o700` (`Client.dump`).
   - `persist_tokens_to_supabase(src_store: str | None = None) -> bool`:
     Lee el almacén local y persiste de forma segura los tokens a Supabase.
   - `login_client(*, prompt: bool = True, ...)`:
     * Si no existen tokens locales válidos, intenta restaurar desde Supabase antes de solicitar credenciales o fallar.
     * Si los tokens locales eran inválidos o caducaron, intenta restaurar desde Supabase antes de requerir credenciales.
     * Tras un inicio de sesión exitoso (sea por token o credenciales), invoca `persist_tokens_to_supabase(store)` dentro de un bloque seguro `try/except`.

4. **Suite de Pruebas Automatizadas**:

     * Restauración local con permisos restrictivos y persistencia a Supabase.
