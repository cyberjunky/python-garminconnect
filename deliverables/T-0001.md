# Entrega T-0001: Especificación y Planificación de Sincronización Recurrente de Tokens y Actualización Vercel

## 1. Resumen Ejecutivo

Se completó la especificación formal y el plan de implementación técnica para resolver de manera definitiva la caducidad periódica de los tokens de autenticación de Garmin Connect en GitHub Actions y mantener la aplicación en producción en Vercel (`apps/web`) sincronizada y actualizada.

La solución adopta una persistencia centralizada en Supabase mediante una tabla dedicada `garmin_tokens` aislada con Row Level Security (RLS) para uso exclusivo de `service_role`. Este esquema permite que el runner de GitHub Actions restaure tokens vigentes antes de la recolección, ejecute el collect diario y vuelva a persistir los tokens renovados al finalizar, eliminando la necesidad de refresco manual o inyecciones periódicas de secretos. Como mecanismo de resiliencia, se mantiene el secreto `GARMINTOKENS_B64` como contingencia y se habilitan scripts locales en el Mac para sincronización asistida. Adicionalmente, se planifica la verificación de build y despliegue a producción de la versión `v0.1.0` en Vercel.
