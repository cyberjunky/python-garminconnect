## 3. Dictamen Técnico: `GARMINTOKENS: ~/.garminconnect` en el Workflow

### Pregunta
En [`.github/workflows/coaching-daily-collect.yml`](file:///Users/alarcondiegof/ies-projects/python-garminconnect/.github/workflows/coaching-daily-collect.yml#L38) y [L52](file:///Users/alarcondiegof/ies-projects/python-garminconnect/.github/workflows/coaching-daily-collect.yml#L52), se define:
```yaml
env:
  GARMINTOKENS: ~/.garminconnect
```
Dado que la virgulilla (`~`) no se expande automáticamente dentro del bloque `env:` de YAML ni en variables de entorno del sistema, ¿el código Python ejecuta `expanduser` o se rompe en runtime?

### Dictamen: **El código no se rompe (expanduser resuelve la ruta)**
1. **Resolución en Python**:
   - En [`scripts/garmin_auth.py:146`](file:///Users/alarcondiegof/ies-projects/python-garminconnect/scripts/garmin_auth.py#L146):
     ```python
     def tokenstore_path() -> str:
         return os.path.expanduser(os.getenv("GARMINTOKENS", "~/.garminconnect"))
     ```
   - En [`garminconnect/client.py:73`](file:///Users/alarcondiegof/ies-projects/python-garminconnect/garminconnect/client.py#L73):
     ```python
     token_path = Path(path).expanduser()
     ```
   Tanto `os.path.expanduser` como `Path.expanduser()` reconocen la virgulilla inicial y la transforman inequívocamente a `/home/runner/.garminconnect` en el entorno Linux del runner.
2. **Pasos Shell del Workflow**:
   - En las líneas 40 y 42 del workflow, los comandos de shell no usan `$GARMINTOKENS`, sino explícitamente `"$HOME/.garminconnect"`:
     ```bash
     mkdir -p "$HOME/.garminconnect"
     if [ ! -f "$HOME/.garminconnect/garmin_tokens.json" ] && [ -n "$GARMINTOKENS_B64" ]; then ...
     ```
   Por ende, hay coincidencia total entre la ruta creada por el shell y la ruta consumida por Python.
3. **Recomendación no bloqueante**:
   Para evitar confusiones a futuro o dependencias de herramientas externas que no hagan `expanduser`, se recomienda como buena práctica cambiar `GARMINTOKENS: ~/.garminconnect` por `GARMINTOKENS: ${{ runner.temp }}/.garminconnect` o `$HOME/.garminconnect` en el YAML del workflow.

```python
    if not isinstance(token_data, dict) or not token_data:
        return None

    di_token = token_data.get("di_token")
    di_refresh = token_data.get("di_refresh_token")
    has_token = bool(di_token and (not isinstance(di_token, str) or di_token.strip()))
    has_refresh = bool(di_refresh and (not isinstance(di_refresh, str) or di_refresh.strip()))
    if not (has_token or has_refresh):
        return None
```
**Dictamen**: **CUMPLE ESTRICTAMENTE**. Si el archivo local contiene `{}` o strings en blanco/nulos, la función retorna `None` de inmediato y no ejecuta ninguna sentencia `upsert` contra la base de datos de Supabase.
