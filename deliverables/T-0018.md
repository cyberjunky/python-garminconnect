### 3.4 Flujo de Excepciones, Observabilidad y Código Inerte en Autenticación
Se auditaron los métodos de autenticación y persistencia de tokens:
1. **Fuga potencial de información en logs**:
   En [`scripts/garmin_auth.py:223,235`](file:///Users/alarcondiegof/ies-projects/python-garminconnect/.ies/worktrees/T-0017/scripts/garmin_auth.py#L223):
   ```python
   except Exception as exc:

   ```
   Registrar `%s, exc` con la representación textual cruda de excepciones de red/HTTP (que pueden contener cabeceras `Authorization`, URLs con parámetros sensibles o respuestas de error de la API) viola el principio de no fugar secretos ni datos de sesión en logs públicos (Art. IV.1 y DEC-004).
2. **Código inerte y persistencia fallida sin advertencia**:
   En [`scripts/garmin_auth.py:182-198`](file:///Users/alarcondiegof/ies-projects/python-garminconnect/.ies/worktrees/T-0017/scripts/garmin_auth.py#L182-L198):
   ```python
   def persist_tokens_to_supabase(src_store: str | None = None) -> bool:
       try:
           ...
           res = upsert_garmin_tokens_to_supabase(token_data)
           return res is not None
       except Exception as exc:
           _LOGGER.debug("Failed to persist tokens to Supabase: %s", exc)
           return False
   ```
   `persist_tokens_to_supabase` captura cualquier excepción internamente, la degrada a nivel `DEBUG` y devuelve `False`.
   Sin embargo, en `login_client` (líneas 217-220, 229-232, 240-243):
   ```python
   try:
       persist_tokens_to_supabase(store)
   except Exception as exc:
       _LOGGER.warning("Could not persist tokens after login: %s", exc)
   ```
   Dado que `persist_tokens_to_supabase` **nunca eleva una excepción**, el bloque `except Exception as exc:` es código muerto inalcanzable. Y como `login_client` no evalúa el valor booleano retornado (`if not persist_tokens_to_supabase(store): _LOGGER.warning(...)`), ante un fallo de conexión o caída de Supabase el sistema falla de manera completamente silenciada sin emitir la advertencia exigida por REQ-005.
3. **Test unitario desacoplado de la realidad**:
   En [`tests/test_collector_privacy_and_resilience.py:146`](file:///Users/alarcondiegof/ies-projects/python-garminconnect/.ies/worktrees/T-0017/tests/test_collector_privacy_and_resilience.py#L146), `test_login_client_logs_warning_on_persist_failure` fue programado inyectando `side_effect=RuntimeError("Supabase connection down")` en el mock de `persist_tokens_to_supabase`.
