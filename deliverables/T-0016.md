# Entrega T-0016: Versionado SemVer 0.3.0 y CHANGELOG de Tri-Coach (apps/web)

## 1. Resumen de Implementación

En cumplimiento del contrato de la task `T-0016`, de la Constitución del proyecto (Artículo III, enmienda ADR-009) y de la disciplina operativa HITL (DEC-001):

### 1.1 Adopción de SemVer y Actualización a 0.3.0
- Se adoptó formalmente el estándar **Semantic Versioning (SemVer)** para el ecosistema unificado de **Tri-Coach**.
- La versión canónica reside en `apps/web/package.json` y `apps/web/package-lock.json`.
- Política de versionado:
  - **MINOR** (0.x.0): Incrementado por cada Pull Request que introduce nuevas funcionalidades o módulos (PR #1 = 0.2.0, PR #2 = 0.3.0).
  - **PATCH** (0.x.y): Reservado para Pull Requests o releases de corrección de defectos o parches puntuales.
- Se actualizaron en sincronía:
  - `apps/web/package.json`: `"version": "0.3.0"` (y `"name": "tri-coach-web"`).
  - `apps/web/package-lock.json`: `"version": "0.3.0"` y `packages[""].version: "0.3.0"`.

### 1.2 Creación de `apps/web/CHANGELOG.md`
- Creado en formato [Keep a Changelog](https://keepachangelog.com/es-ES/1.1.0/) íntegramente en español.
- **Alcance integral**: El encabezado aclara explícitamente que cubre todo el sistema **Tri-Coach**:
  1. Aplicación web y dashboard Next.js (`apps/web/`).
  2. Recolector y análisis fisiológico en Python (`garmin_coaching/`, `services/collector/`, `scripts/garmin_auth.py`).
  3. Flujos de automatización CI/CD de GitHub Actions (`.github/workflows/`).
  4. Esquema relacional y migraciones de Supabase (`supabase/migrations/`).
- **Historia retroactiva reconstruida desde `git log`**:
  - `[0.3.0] - 2026-10-13` (PR #2, rama `ux/audit-2026-10`): Auditoría UX integral (P1, P2 y P3 en T-0012 y T-0013), unificación de marca Tri-Coach, correcciones de zona horaria Bogotá UTC-5, layout responsive móvil `minmax(0, 1fr)` con `scrollWidth == 375`, accesibilidad con skip-links y `aria-current`, copia en español sin fugas técnicas, y triggers Supabase `moddatetime` (`updated_at`).
  - `[0.2.0] - 2026-10-13` (PR #1, merge `0d81139`): Shell con barra lateral persistente (`DashboardNav`), chat con modelos OpenAI, botón de actualización bajo demanda (`workflow_dispatch`), persistencia de última actividad deportiva (commit `b13aa16` del 3-oct) y sincronización de tokens Garmin en Supabase (SPEC-001).
  - `[0.1.0] - 2026-09-25` (MVP inicial, commit `102430e`): MVP dashboard, recolección diaria automatizada, gráfica de preparación física 0–100, desglose de mesociclos, seguimiento al reto 70.3 Cartagena y marca de tiempo en hora de Bogotá.

### 1.3 Documentación en `apps/web/README.md`

  - Versión actual (`0.3.0`).
  - Regla SemVer para el ecosistema Tri-Coach.

- El archivo `README.md` raíz del repositorio **NO** fue tocado, preservando la separación de capas.

### 1.4 Verificación de Versión en la Barra Lateral
- `apps/web/app/(dashboard)/layout.tsx` importa `pkg` desde `package.json` y ejecuta:
  ```typescript
  function appVersion(): string {
    const sha = process.env.VERCEL_GIT_COMMIT_SHA?.slice(0, 7);
    return sha ? `v${pkg.version} · ${sha}` : `v${pkg.version}`;
  }
  ```
- En entorno local (`VERCEL_GIT_COMMIT_SHA` no definido), la función evalúa exactamente a `v0.3.0`.
- Este valor se transfiere a `<DashboardNav version={appVersion()} />`, mostrándose al pie de la barra lateral mediante `<p className="dash-version">{version}</p>`.
- Se validó mediante test automatizado en `apps/web/lib/version.test.mjs`.

### 1.5 Suite de Pruebas Unitarias
- Se creó `apps/web/lib/version.test.mjs` con 4 tests que validan:
  1. Consistencia de versión `0.3.0` entre `package.json` y `package-lock.json`.
  2. Cobertura del changelog (0.1.0, 0.2.0 con b13aa16/0d81139/SPEC-001, y 0.3.0, con declaración de alcance integral).
  3. Existencia de la sección 'Versión y cambios' y enlace en `README.md`.
  4. Generación de la cadena `v0.3.0` para la barra lateral.
- La suite completa de `apps/web` cuenta ahora con **13 tests en verde** (tiempo de ejecución: 145 ms).
