# Entrega T-0012: Corrección de datos P1 y responsive móvil en apps/web y backend

## 1. Resumen de Cambios

Se implementaron todos los puntos de la sección **P1 (Datos incorrectos y Móvil)** documentados en `docs/ux-audit-2026-10-13.md`, respetando la disciplina SDD y sin force-push:

1. **Hora de última actividad (`apps/web/lib/lastActivity.ts`)**:
   - `start_time_local` de Garmin no incluye huso horario. Se normaliza tratándolo como representación UTC (`${normalized}Z`) y formateando en UTC (`timeZone: "UTC"`).
   - Resultado: Una actividad registrada a las `11:11:04` se formatea exactamente como `11:11` en cualquier entorno (servidor Vercel en UTC, cliente local en Bogotá, Tokio, etc.), eliminando el desfase de 5 horas que mostraba `06:11`.

2. **`updated_at` en backend y migración SQL idempotente**:
   - En `services/collector/supabase_client.py`: Se incorporó explícitamente `"updated_at": now_iso` en las 5 tablas de `upsert_daily_payload` (`readiness_daily`, `training_load`, `daily_snapshots`, `session_log`, `weekly_sport_load`).
   - En `supabase/migrations/20261013_updated_at_triggers.sql`: Se entregó la migración SQL idempotente con `create or replace function public.set_updated_at()` y `drop trigger if exists / create trigger ... before update` para las tablas con upsert (`daily_snapshots`, `readiness_daily`, `training_load`, `session_log`, `weekly_sport_load`, `garmin_tokens`).
   - Se actualizó también `supabase/schema.sql` para reflejar los triggers en instalaciones base.

3. **BB delta con signo (`apps/web/app/(dashboard)/page.tsx`)**:
   - Se condicionó el signo `+` únicamente cuando `readiness.bb_change > 0`.
   - Si es negativo (ej. `-12`), se renderiza `-12` en lugar de `+-12`. Si es `0`, se renderiza `0`.

4. **Tarjeta de recuperación dinámica (`apps/web/components/RecoveryMilestonesCard.tsx`)**:
   - Se desacopló de la fase estática "R0" y de la fecha fija "meta: 5 oct 2026".
   - Ahora recibe `macrocycle` de `payload.macrocycle`, renderizando dinámicamente el nombre y código de fase (ej. `Base aeróbica (R1)`), los días restantes calculados hasta `macrocycle.end` (si está presente), y solo muestra la línea de meta si viene en los datos del backend (`end` o `focus`).
   - El estado de ACWR muestra dinámicamente `ACWR en rango {code} ✓`.

5. **Fecha local Bogotá en dashboard (`apps/web/lib/lastUpdated.ts`)**:
   - Se creó y exportó la función auxiliar `todayBogotaIso(date: Date = new Date())` que formatea la fecha actual en `America/Bogota` (`YYYY-MM-DD`).
   - Se integró en:
     - `apps/web/app/(dashboard)/mesociclos/page.tsx:9`
     - `apps/web/app/(dashboard)/page.tsx:42`
     - `apps/web/app/(dashboard)/retos/page.tsx:30`
   - Evita el salto prematuro de fecha a las 19:00 hora Bogotá ocasionado por `new Date().toISOString().slice(0, 10)`.

6. **Menú móvil compacto (`apps/web/app/globals.css`)**:
   - Se sustituyó la barra lateral vertical sticky de 336 px (41% del alto) por una barra de navegación horizontal compacta (`~44px` de alto, correspondiente a **5.4%** de la pantalla en 375×812, cumpliendo holgadamente el criterio `<15%`).
   - Se configuró `position: sticky; top: 0; z-index: 100; background: #0b1220;` con scroll horizontal táctil suave (`-webkit-overflow-scrolling: touch; scrollbar-width: none;`).
   - Se ocultó la etiqueta de versión en móvil (`.dash-version { display: none; }`) para mantener la barra limpia y compacta.

7. **PreparationChart legible en móvil (`apps/web/app/globals.css`)**:
   - Se fijó `min-width: 680px` en `.prep-chart` con contenedor scrollable `.prep-chart-wrap { overflow-x: auto; -webkit-overflow-scrolling: touch; }`.
   - En pantallas móviles de 375 px, las fuentes de 9–10 px se mantienen nítidas (~7.1 px equivalentes escalados) y el usuario puede desplazarse horizontalmente a lo largo de la línea temporal sin pérdida de legibilidad.

8. **Color-scheme oscuro y Theme Color (`apps/web/app/layout.tsx` y `globals.css`)**:
   - Se agregó `color-scheme: dark;` a `:root` en `globals.css`.
   - Se exportó `viewport: Viewport` en `layout.tsx` con `themeColor: "#0f172a"` y `colorScheme: "dark"`.

## 2. Script SQL Idempotente para Supabase

Archivo: `supabase/migrations/20261013_updated_at_triggers.sql`
Listo para ejecutar directamente en el **SQL Editor de Supabase**:

```sql
-- Idempotent triggers to automatically maintain updated_at = now() on tables with upsert operations.
-- Can be executed safely in Supabase SQL Editor.

create or replace function public.set_updated_at()
returns trigger as $$
begin
  new.updated_at = now();
  return new;
end;
$$ language plpgsql;

-- 1. daily_snapshots
drop trigger if exists trigger_set_updated_at on public.daily_snapshots;
create trigger trigger_set_updated_at
before update on public.daily_snapshots
for each row execute function public.set_updated_at();

-- 2. readiness_daily
drop trigger if exists trigger_set_updated_at on public.readiness_daily;
create trigger trigger_set_updated_at
before update on public.readiness_daily
for each row execute function public.set_updated_at();

-- 3. training_load
drop trigger if exists trigger_set_updated_at on public.training_load;
create trigger trigger_set_updated_at
before update on public.training_load
for each row execute function public.set_updated_at();

-- 4. session_log
drop trigger if exists trigger_set_updated_at on public.session_log;
create trigger trigger_set_updated_at
before update on public.session_log
for each row execute function public.set_updated_at();

-- 5. weekly_sport_load
drop trigger if exists trigger_set_updated_at on public.weekly_sport_load;
create trigger trigger_set_updated_at
before update on public.weekly_sport_load
for each row execute function public.set_updated_at();

-- 6. garmin_tokens
drop trigger if exists trigger_set_updated_at on public.garmin_tokens;
create trigger trigger_set_updated_at
before update on public.garmin_tokens
for each row execute function public.set_updated_at();
```
