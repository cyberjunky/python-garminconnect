# Entrega T-0006: Soporte Adaptativo de Temperature para Modelos Reasoning en `/api/chat`

## 1. Contexto y Problema

En `apps/web/app/api/chat/route.ts`, las solicitudes al endpoint de completions de OpenAI (`https://api.openai.com/v1/chat/completions`) enviaban de forma estática `temperature: 0.4`.

Modelos de razonamiento y familias avanzadas (tales como `gpt-6.1-sol`, `o1`, `o3-mini`, `gpt-5`, etc.) no aceptan configuraciones de temperatura arbitrarias, admitiendo únicamente el valor por defecto (`1`). Cuando se enviaba `temperature: 0.4`, OpenAI rechazaba la petición con el error:
> *"Unsupported value: 'temperature' does not support 0.4 with this model. Only the default (1) value is supported."*

Esto provocaba respuestas `502 Bad Gateway` en la interfaz web al seleccionar dichos modelos.

---

## 2. Solución Implementada

En `apps/web/app/api/chat/route.ts`:
1. **Detección Adaptativa de Modelos**:
   - Se introdujo la expresión regular `FIXED_TEMP_MODELS = /^(o\d|gpt-5|gpt-6|chatgpt-)/i`.
   - Si el modelo seleccionado coincide con esta expresión o pertenece a familias de temperatura fija, se omite el campo `temperature` en el payload JSON hacia OpenAI (permitiendo que OpenAI aplique su valor por defecto 1 automáticamente).
   - Para modelos estándar (`gpt-4o`, `gpt-4o-mini`, `gpt-4.1`, etc.), se envía `temperature: 0.4`.

2. **Mecanismo de Reintento Automático Resiliente**:
   - Si la llamada inicial incluye `temperature` y OpenAI responde con error mencionando `"temperature"` (por ejemplo ante modelos nuevos o casos borde no contemplados por la regex), la función auxiliar `executeOpenAiChatCompletion` reintenta de forma transparente e inmediata la solicitud omitiendo el parámetro `temperature`.
   - Se previene así el fallo 502 al usuario final ante cualquier modelo con restricción de temperatura.
